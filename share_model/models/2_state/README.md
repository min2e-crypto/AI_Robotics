# 2번 모델: 차량 상태 분류 — **임시 버전 (state_v2)**

| 항목 | 값 |
|---|---|
| 파일 | `best.pt` (실행 이름 `state_v2`) |
| 모델 | YOLO26n-cls, 입력 크기 224 |
| 입력 | 1번 박스를 **정사각형으로 자른 이미지** (긴 변 × 1.3, 화면 밖은 회색 114). `vision.py`의 `crop_square()` |
| 클래스 | `normal`(정상), `damaged`(파손), `overturned`(전복). 모델 안의 번호는 알파벳순(damaged=0, normal=1, overturned=2)이라 **번호 말고 이름으로** 쓸 것 |
| 애매(`uncertain`) | 학습 클래스가 아니라 규칙. 아래 표 |

## 애매 규칙 (`vision_config.yaml`의 `state`)

| 규칙 | 기준 | 비고 |
|---|---|---|
| `too_small` | 박스 긴 변 < 24px | 분류하지 않음 |
| `low_conf` | 최고 확률 < 0.6 | |
| `small_margin` | 1등 − 2등 < 0.2 | 3클래스라 최고 확률이 0.6 이상이면 차이가 항상 0.2 이상 → **사실상 작동 안 함** |
| `risky_normal` | 정상이 1등이어도 파손+전복 ≥ 0.3 | 2번이 위험 차를 정상으로 확신하는 문제 때문에 추가 (기준값은 임시) |

## 학습 데이터 (사람이 키보드로 한 장씩 분류)

| 출처 | 라이선스 | 비고 |
|---|---|---|
| AccidentDetection-9k (Mendeley) | CC BY 4.0 | 1,500장 표본. 구글 이미지 수집, AI 생성으로 보이는 사진 섞임 |
| AIDER traffic_incident / normal (Zenodo) | 비상업·학술 | 드론·항공 시점 |
| AirSynDrone (Roboflow) | **미확인** | 실제 차·장난감 차 혼합. 대부분 아직 미분류 |
| AerialShi (Roboflow) | MIT | 전복(180°)·정상 |

train 기준 정상 1,473 / 파손 321 / 전복 57. **전복이 매우 적다.**

## 성능 (val: 정상 184 / 파손 41 / 전복 8)

| 지표 | 값 |
|---|---|
| 파손 Recall (1등 그대로) | 0.610 |
| 파손 Recall (애매 규칙 적용) | 0.585 |
| 위험 차(파손+전복) → 정상으로 틀림 | **0.306** (목표 0.02에 크게 못 미침) |
| 관제자 확인으로 넘어가는 비율 | 3.4% |
| 정상 차를 위험으로 잘못 판정 | 1.6% |

- val 파손이 41대, 전복이 8대뿐이라 숫자가 ±0.15 정도 흔들릴 수 있다. 전복 성능은 판단 불가.
- test는 아직 한 번도 쓰지 않았다 (최종 모델을 정한 뒤 한 번만).

## 알려진 약점 — **이 모델이 지금 가장 큰 병목**

- 실제 CCTV 사고 사진 30장 시험에서, **옆으로 누운 트럭·SUV, 뒤집힌 승용차, 비스듬한 시점의 앞부분 파손차를 '정상'으로 확신**했다.
- 학습 데이터가 위에서 내려다본 승용차 위주라서로 추정.
- 반대로, 문이 열린 채 서 있는 차를 '전복'으로 판정한 사례도 있음.
- 결론: 지금은 `state`를 그대로 믿기보다 **`uncertain`과 위험 판정을 관제자 확인으로 넘기는 구조**가 필요하다.

## 앞으로

- 비스듬한 CCTV 시점 데이터(AI Hub 교통사고 영상 신청 예정)로 재학습할 예정. 바뀌면 `best.pt`만 교체.
