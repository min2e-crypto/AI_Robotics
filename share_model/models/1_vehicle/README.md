# 1번 모델: 차량 탐지

| 항목 | 값 |
|---|---|
| 파일 | `best.pt` (실행 이름 `visdrone_v1-2`), `yolo26s_coco.pt` (보조) |
| 모델 | YOLO26s, 입력 크기 960 |
| 클래스 | `vehicle` 하나 (VisDrone의 car·van·truck·bus를 합침). 사람·오토바이·자전거는 일부러 뺌 |
| 학습 데이터 | VisDrone2019-DET (드론 시점, 실제 도로). train 6,471장, 차량 박스 188,624개 |
| 증강 | 회전 180°, 상하·좌우 반전 (항공 시점이라 차 방향이 제각각) |
| val 성능 | Precision 0.899 / Recall 0.771 / mAP50 0.863 / mAP50-95 0.579 |
| test 성능 | **미측정** (VisDrone test-dev) |
| 속도 | 장당 약 3ms (RTX 4070 Ti SUPER). 맥북 속도는 미측정 |

## 보조 모델 `yolo26s_coco.pt`를 같이 쓰는 이유

- 1번은 드론에서 내려다본 사진으로만 배워서, **비스듬한 CCTV·지면 시점의 차를 놓치는 경우**가 있다.
- 그래서 Ultralytics 기본 COCO 모델(car·bus·truck만 사용)을 같이 돌리고 결과를 합친다.
  - 두 박스의 IoU가 0.5보다 크거나, 작은 박스의 80% 이상이 큰 박스 안에 있으면 같은 차로 보고 확신도 높은 쪽 하나만 남긴다.
  - 80% 규칙은 한 차에 박스가 2개 나온 사례(시험 사진 27번) 때문에 추가했다.
- 안 쓰려면 `vision_config.yaml`의 `coco: none`.

## 알려진 약점 (결과 그림을 보고 확인한 것)

1. **화면을 가득 채우는 큰 트럭:** 박스가 여러 개로 쪼개지거나, 트랙터·트레일러가 따로 잡힘. 확신도 0.27~0.42로 낮음.
2. **차가 아닌 물체를 차로 잡음:** 콘크리트 블록 더미(0.58~0.75), 방수포 덮인 짐, 창고 모서리, 흰 판자, 중앙분리대 표지판. 위에서 보면 직사각형인 물체에 약하다.
3. **뒤집힌 차를 놓칠 수 있음:** 뒤집힌 차를 학습한 적이 없다. 야간 전복 트럭, 형체가 거의 없는 잔해를 놓친 사례가 있음.
4. **박스 아랫변이 실제 바퀴보다 내려가는 경우:** 젖은 노면 반사, 차 옆에 선 사람이 박스에 섞임. 도로 좌표로 바꿀 때 수 m 오차가 남 (시험 사진 27번: 약 85px = 약 9m).
